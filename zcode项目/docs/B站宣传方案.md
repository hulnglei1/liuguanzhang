## 一、先说结论

**用实机录屏 + 后期剪辑，不要用"写代码动画"那类 skill 做宣传片。**

理由：
- 这游戏卖的是**手感 + 原著梗 + 荒诞对白**，观众是玩家，不是开发者
- 代码动画会让人误以为"这是个程序员自嗨的玩具"，反而劝退
- 真要讲技术，那是**第二支视频**的事（见第五节）

## 七、浏览器自动上传：能做什么、不能做什么

**能做**（修好环境后）：打开 B站创作中心 → 填标题/简介/标签/分区 → 选封面文件 → 填投稿信息。
**不能做**：登录（扫码）、验证码、风控确认、最终"投稿"点击。

> 现状：**agent-browser 在这台机器上第一次 `open` 卡死了**（留下一个关不掉的空白窗口，
> 已强制清理）。原因大概率是 Chromium 尚未安装完成，`open` 时在后台下载/启动而没有超时保护。
>
> 修复顺序：
> 1. `agent-browser install`（先把 Chromium 装好，单独跑，带超时）
> 2. 之后每次 `open` 都加超时，失败立刻回退
> 3. 任何时候都不要让 `open` 在前台裸跑（这次就是这样挂住的）

**建议**：我先把标题/简介/标签/封面/分镜全部备齐（上面已给），
你复制粘贴投稿，**3 分钟搞定**；等我把浏览器环境修好，可以再试自动填表单，
但扫码那一步仍然要你来。

## 附录：自动化链路（已打通，2026-11-09 晚）

### 录制素材（自动，无需人工操作）
```
.tools/record_promo.py    驱动游戏打出关键镜头 + 后台抓帧（JPEG 直存，~15fps）
.tools/build_promo.py     PIL 生成中文标题卡 + ffmpeg 补帧到 30fps + 拼接
.tools/build_promo_v2.py  v2：换开场顺序 + 结尾 GitHub 卡 + 铺 BGM
```
关键前提：给 MCP 桥接的 `capture_screenshot` 加了 `jpg_path` 参数
（PNG 编码 1280×720 要 ~25ms，是录帧瓶颈；JPEG 只要几毫秒）。

### 成片
| 版本 | 时长 | 内容 |
|---|---|---|
| v1 | 31s | 序章 → 战场 → 咆哮 → 飞箭 → 大地图（标题卡，无声） |
| **v2** | **35s** | **开场换成咆哮（张飞立绘）→ 序章 → 战场 → 飞箭 → 大地图 → 结尾 GitHub 卡，配 bgm_battle + bgm_win** |

文件在 `推广视频/候选素材/`。

### 浏览器上传
用 `web-access` skill 的 CDP 模式（直连自己的 Edge，带登录态），
不要用 `agent-browser`（它自己下载 Chromium，第一次 open 会挂死）。

Windows 上的完整启动配方见 `.workbuddy/memory/2026-11-08.md` 的
「浏览器自动化的正确姿势」一节。要点：
- Edge 必须用**独立 user-data-dir** + `--remote-allow-origins=*`
- 手工写 `DevToolsActivePort` 指针，第二行是**完整路径** `/devtools/browser/<id>`
- 代理要单独常驻（check-deps 退出会把它一起带走）

### 仍需人工的一步
B站登录（扫码）。登录后 `/eval` 读 `location.href`，
不含 `passport.bilibili.com` 即为已登录，之后可自动填标题/简介/标签/封面并上传。

## 附录二：v3 —— 飞箭镜头怎么才拍出来（2026-11-09 深夜）

用户反馈"箭追着跑的效果根本没体现在视频里面"。查下来是**三个叠加的坑**：

### 坑 1：箭每回合只走 1 格，回合要 6 秒
原速下箭是"每隔 6 秒跳一格"，看起来就是**没动**。
→ **必须边录边推进回合**（按两次空格结束我方回合，等敌方演完，箭才前进 1 格）。

### 坑 2：公孙瓒一回合只能射一支 → 天上永远只有一支箭
原著是「朝天上连射数箭……犹如人形防空炮」。
→ **连续 6 个回合各射一支**（CD 0），天上同时挂 6 支，各自追各自的敌人 = 箭雨。

### 坑 3：技能演出的大立绘把战场挡住
华雄的技能演出会盖住半个画面。
→ 用 numpy 逐帧扫描：**亮灰白像素占比 > 2% 判为有立绘**，只取干净区间。

### 最终做法
```
录制：.tools/record_arrow4.py   连射 6 回合 + 推进回合 + 全程抓帧（705 帧）
筛选：numpy 找"无立绘"的连续区间（帧 0-407）
成段：ffmpeg crop 624×351 → scale 1280×720 → setpts=2.4*PTS（慢放 2.4 倍）
合成：.tools/build_promo_v3.py
```
慢放段 19.9 秒，成片 v3 共 51 秒。

### 顺带发现的 API 细节
- MCP 桥接的 `get_battle_state` **没有暴露飞弹状态**（没有 arrows 字段），只能从画面判断
- 单位状态里**没有 alive 字段**，判断存活要用 `hp > 0`
- 抓帧和操作**必须用两个独立 socket**（共用一个会响应串位，主线程随机拿到空响应）
