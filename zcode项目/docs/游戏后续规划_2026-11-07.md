### 为什么 UI 图标没做

现有界面用 emoji + 文字，功能上不缺；换成 PNG 图标要动主菜单、战斗面板、设置面板多处布局，
而收益是"看起来更像成品游戏"，属于锦上添花。按优先级标准（成本 < 0.5 天且收益明确才插队），
这项性价比不达标，**先不做**，等界面要做整体改版时一并处理。

## 三、建议的四个批次

### 批次 1 · 音频闭环（约 1 天）★ 最推荐先做

| 项 | 内容 | 验收 |
| :--- | :--- | :--- |
| BGM | 3 首循环：主菜单 / 战场 / 胜利结算 | 进出场景能听到、能循环、无爆音 |
| 音频总线 | Master / BGM / SFX 三条 | 分别调音量互不影响 |
| 设置菜单 | 音量滑条 + 全屏开关记忆 + 按键说明 | 退出重进保持设置 |
| 音效补点 | 抽奖、图鉴翻页、按钮通用点击 | 无"该响不响" |

> 为什么排第一：现在音效有了但**没有配乐**，玩家感受是"打了半天很干"；
> 而设置菜单是**唯一能救回"太吵/太小"体验**的东西，成本极低。

## 四、优先级判断标准（以后就用这三条）

1. **玩家第一眼/第一分钟能感知的** > 内部整洁
2. **影响"能不能玩下去"的**（卡死、看不懂、没反馈） > 锦上添花
3. **成本 < 0.5 天且收益明确**的，插队做；**需要 > 3 天**的，先拆成能验收的小块

反面例子（当前不做）：
- 剧情分支——笑点靠"一路狂飙"，分支会打散节奏，维护成本是乘法
- 32 个单位全做序列帧——单个成本不高，乘 22 就爆了；用 shader 呼吸替代
- 重做 VFX——现在的程序化青龙/震屏/全屏闪是强项，别动

## 五、每批的验收方式（避免"做完了但没验"）

| 批次 | 自动化 | 人工 |
| :--- | :--- | :--- |
| 音频 | `probe_presentation`（流可加载、时长正常） | 实际听：切换场景、调音量、循环接缝 |
| 内容 | 新关卡加 `probe_chN_flow` + 通关脚本 | 完整打一遍新关 |
| 表现 | 截图对比 + 帧数检查 | 看呼吸是否"晃"、表情切换是否跳帧 |
| 技术债 | 全量回归 36+ 项必须全绿 | — |
