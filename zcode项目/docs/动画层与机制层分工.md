> 两个 agent 并行开发的边界约定。**动画侧读第三节起即可开工**，无需了解战斗逻辑。

## 一、为什么需要这份文档

`scripts/battle.gd` 有 3200+ 行，**单位视觉与战斗逻辑原本混在一起**。
两个 agent 同时改同一个文件 = 后写的直接覆盖先写的（同一工作目录，非 git worktree）。

为此已做一次抽离：把"单位外观 / 呼吸 / 攻击演出"集中到 `scripts/ui/unit_view.gd`。
之后两个 agent 的文件集合**零重叠**，可以真正并行。

## 三、唯一接口（battle.gd 调用动画侧的全部入口）

机制侧只调这三个 static 函数，**签名已冻结**（要改先商量）：

```gdscript
# 1. 构建单位外观。返回 true = 用了贴图，调用方会隐藏色块底盘
UnitViewCore.build_art(node: Node2D, unit_id: String, tile: float) -> bool

# 2. 攻击演出。node 是单位节点，target_px 是目标格中心像素坐标
UnitViewCore.play_attack(node: Node2D, target_px: Vector2) -> void

# 3. 拿全屏特效层（刀光/斩击都挂这里，与单位节点解耦）
UnitViewCore.ensure_fx_layer(root: Node) -> Node2D
```

**节点内部结构约定（可以改，但要知道机制侧依赖什么）**

| 节点名 | 类型 | 机制侧是否依赖 |
|---|---|---|
| `ArtAnim` | AnimatedSprite2D | 否（只在 unit_view 内使用） |
| `Art` | Sprite2D | 否 |
| `Plate` / `CharLabel` | Polygon2D / Label | 否（色块回退用） |
| `HPBarFill` / `HPBarBg` | ColorRect | **是** —— `_sync_text()` 每帧按血量改宽度 |
| `NameLabel` | Label | **是** —— 显示单位名 |
| `Rim` | Polygon2D | 否（阵营金边） |

即：**血条与名字标签的节点名和层级不要动**，其余随便改。

## 四、动画侧的三个任务（对齐"战棋黄金法则"）

原理：只出 **1 张极品母图**，本体不做多帧画皮。靠代码把"动感"造出来。

### 任务 1：待机呼吸 —— 锁脚 Shader
- 落点：`unit_view.gd` 的 `apply_idle_breath(sprite)`
- 目标：脚底钉死在格子上，上半身轻微起伏；**零漂移、绝对不晃**
- 推荐：Shader 顶点位移（新建 `assets/shaders/unit_breath.gdshader`），纯 GPU、零 CPU
- 备选：Tween 缩放 `scale.y`，但**轴心必须设在脚底**，否则会上下漂

### 任务 2：攻击演出 —— 代码驱动冲刺
- 落点：`unit_view.gd` 的 `play_attack(node, target_px)`
- 现状（基线，可优化）：0.09s 前冲 14px → 0.14s 回弹，TRANS_QUAD
- 可加：微前倾（节点 `rotation` 小角度，注意会连影子一起转）、命中顿挫（短暂停顿 0.03s）、
  击中帧同步特效

### 任务 3：视觉爆发 —— 独立全屏特效层
- 落点：`ensure_fx_layer(root)` 拿到的 `UnitFxLayer`（z_index 70）
- 刀光斩击、青龙虚影、震屏都挂这里，**不要挂在单位节点下**
- 这样单位移动/死亡/重生都不会影响特效，反之亦然

## 五、硬约束（违反会产生经典战棋 bug）

1. **落点归位**：`node.position` 的"落点"由机制侧按格子计算。
   冲刺位移只能作临时偏移，**动画结束必须回到原位**（`play_attack` 里已有 `tw.finished` 兜底）。
   违反 = 单位位置与逻辑格子脱节 = 滑步 / 点了不动
2. **动画不改数值**：不得改 HP、坐标、`acted`、`moved_this_turn` 等任何战斗状态
3. **缺图安全回退**：`build_art` 返回 `false` 即可，调用方显示色块。不得报错、不得留空白节点
4. **注意 `queue_free` 是延迟的**：清旧节点后同帧再加新节点是允许的，但别依赖 `get_child_count()` 立刻归零
5. **导出兼容**：加载帧不要用 `DirAccess` 列目录（导出成 pck 后列不到），用 `ResourceLoader.exists` 逐个探测 —— 参照 `unit_art.gd: _load_frame_dir()`


| 测试 | 检查什么 |
|---|---|
| `probe_anim` | idle/attack 帧数、战场节点是否用 AnimatedSprite2D、攻击切 attack、播完复位 idle、缺图回退 null |
| `probe_ch1_check` | 飞弹延迟、放完技能不可再动、**覆盖层无残留** |

## 七、素材规范（摘要，详见《美术资源规范与AI生图指南》）

```
assets/units/{unit_id}_idle/0.png ~ 3.png     呼吸，循环，3 fps
assets/units/{unit_id}_attack/0.png ~ 3.png   攻击，单次，10 fps
assets/units/{unit_id}.png                    单张静图（无序列帧时的回退）
```

- 三套帧**同画布同锚点**（192×192，脚底贴底），尺寸差一点播放就会抖
- 编号**不能断档**（0,1,2,3 中间空一个，加载器就停在那里）
- **只出"朝右"一套**，朝左自动 `flip_h`

> 注：按"黄金法则"，武将其实只需 1 张母图即可跑通；序列帧是可选增强。
