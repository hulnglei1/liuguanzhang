# Godot 4 战棋开发 · 程序经验笔记

> 调研时间：2026-09。目标：为《魂穿刘关张》战棋项目在 Godot 4 落地的**程序侧关键决策**做记录。
> 原则：凡是「从零写会踩坑」的地方，优先用引擎现成能力；凡是「引擎没有的机制」，用 GDScript 补。

---

## 一、版本选型（重要）

**结论：直接用 Godot 4.7.2 标准版（当前最新稳定版，2026-08 发布）。**

- 不要用 4.2 或更早：本调研发现 4.x 近年持续迭代，4.7 已含多年改进（渲染、TileMap、GDScript、UI 系统都更成熟）。
- **选标准版（GDScript），不选 .NET 版**：
  - .NET 版导出 Web 平台长期受限/不便，标准版 GDScript 导出 Web 无问题（符合「浏览器直玩」目标）。
  - GDScript 是 Python 风格，AI 生成正确率高、上手快。
- 下载：官网 godotengine.org → Download → **Godot 4.7.2 standard（.exe 绿色版）**，解压即用，无需安装。

## 二、中文显示（第一坑，必须提前处理）

**Godot 4 默认字体 Open Sans SemiBold 不含 CJK（中文）字形。** 不做处理，中文全部显示为方块（□）。

解决方案（三选一，建议组合）：
1. **打包中文字体**：放一个含中文的 `.ttf/.otf`（如思源黑体、微软雅黑——微软雅黑在 Windows 上可直接复制 `C:/Windows/Fonts/msyh.ttc` 到项目）到 `assets/fonts/`，做成主题默认字体。
2. **系统字体回退**：用 `SystemFont` 资源，设置字体名（如 `"Microsoft YaHei"` / `"sans-serif"`），Windows 上可用。
3. **最佳实践——Fallback**：主字体保持西文友好，中文字体加进 **Fallbacks 数组**（导入设置 → Advanced → Fallbacks），中西文混排自动回退。

**本项目做法**：`assets/fonts/` 放中文字体，做一个 `theme.tres` 全局默认主题，所有 UI 控件统一走该主题。**美术/中文占位图不依赖系统字体**，避免换机显示差异。

## 三、战棋核心实现模式（成熟套路，直接用）

> 这些是战棋类型的「标准答案」，不需要发明，Godot 均有原生支持。

### 3.1 网格与地图
- **用 `TileMapLayer`（Godot 4.3+ 取代了旧 TileMap）** 做地面，`TileSet` 定义地形瓦片（平原/障碍/目标点）。
- 障碍物：要么放 TileSet 里的「障碍瓦片」，要么单独用 `StaticBody2D`/标记节点，两种都行，**推荐 TileSet 里做**（寻路时直接查瓦片属性）。
- 战场逻辑坐标：**用 `Vector2i` 格子坐标**，与像素坐标分离（`map_to_local` / `local_to_map` 转换）。

### 3.2 移动范围与寻路
- **BFS（广度优先）**：从单位格出发按 MOV 扩散，天然给出「可到达格 + 最短路径」，战棋标准做法，O(格数) 足够。
- Godot 无内置 A*/BFS，但手写 BFS 约 30 行 GDScript，纯逻辑放 `scripts/core/grid.gd`（可单测）。
- 路径高亮：可到达格用一个 `TileMapLayer` 覆盖层（半透明格子）或 `Node2D` 方块组。

### 3.3 回合系统
- 状态机：`PLAYER_TURN → ENEMY_TURN → (结算) → PLAYER_TURN`，用枚举 + `turn.gd` 管理。
- **单位行动标记**：每个单位 `acted = true/false`，我方回合结束条件是「所有存活单位 acted」或玩家主动「结束回合」。
- 敌人 AI：V1 用确定性脚本（见设计文档），每回合给每个存活敌人发 `act()` 调用。

### 3.4 技能范围与目标选择
- 技能范围计算 = 格子距离（切比雪夫/曼哈顿/欧氏距离按技能定），BFS 或纯距离判断。
- 目标高亮：选中单位 → 计算技能可命中格 → 覆盖层高亮 → 点击目标格结算。
- **结算引擎与渲染分离**（沿用架构草图）：`combat.gd` 只返回事件数组（伤害/暴击/眩晕），渲染层播放动画。**这为将来 AI agent 驱动、回放、无头测试留了口。**

### 3.5 合体/骑乘
- 关羽骑赵云：合体时两单位合并为一个节点（或一个单位持有 `rider_id`），移动用赵云的 MOV、攻击用关羽 ATK。
- 状态字段放 Unit 上：`mounted` / `rider`（架构草图已定义）。

## 四、对话/文本系统（战棋的重头）

- 用 Godot **UI 系统（Control 节点）** 做对话框：`PanelContainer + RichTextLabel + 头像 TextureRect + 名字 Label`。
- **数据驱动**：对话文本全放 `data/dialogs/*.json`，脚本只负责「读 JSON → 显示」，机制与文本彻底分离（换文本不动代码）。
- 支持多视角（旁白/内心戏/角色名）：JSON 结构 `{speaker, avatar, text, mood}`，渲染时切换名字颜色与头像。
- **打字机效果**：`RichTextLabel.visible_characters` 逐字显示，配合旁白停顿，喜剧节奏关键。

## 五、存档

- `state.gd` 把整个游戏状态序列化为 Dictionary → `JSON.stringify` → `FileAccess` 存到 `user://`（Godot 用户目录，跨机安全）。
- 存档内容：队伍、声望、图鉴、已通关卡、解锁技能。**战斗中途不存档**（关卡制，简化）。

## 六、AI agent（LLM）驱动预留（与本项目核心目标对齐）

> 架构草图中的「LLM 接口预留」在 Godot 里的具体落法：

- **HTTP 调用**：Godot 4 内置 `HTTPRequest` 节点，可直接 POST 到 LLM API（OpenAI/本地 Ollama 均可）。V1 不做，V2 加。
- **铁律：LLM 只产「文本 + 建议」，不直接写游戏状态。**
  - 敌方策略：LLM 返回「建议行动」，由 `turn.gd` 校验合法性后执行（不合法丢弃）。
  - 沙雕对白/报纸：LLM 生成文本 → 走 dialog 系统显示，不进战斗数值。
  - 事件/关卡：LLM 生成 `chapter*.json` 草稿 → 人工/校验器审核 → 注入 data/。
- **好处**：战斗逻辑纯函数化后，甚至可做「AI 自动试玩」来平衡关卡（无头跑 `combat.gd`）。

## 七、占位美术策略（M0 不碰正式美术）

- 单位：先用 `ColorRect` / 绘制的色块 + 武将名 Label（或 `Polygon2D` 画个圆）。
- 技能特效：`GPUParticles2D` / `Tween` 动画占位（青龙斩 = 一条拉长的矩形+渐变，先能看）。
- **目的**：M0 验证的是「玩法手感」，不是画面。美术等手感定了再投入。
- Godot 自带图标 `icon.svg` 可用于临时占位。

## 八、开发工作流（AI agent 友好）

- **所有场景 `.tscn` 和资源 `.tres` 都是文本文件**，可直接被 AI 读写、diff、重构——这是选 Godot 的关键理由之一。
- 约定：
  - 纯逻辑脚本（无渲染）放 `scripts/core/`，**不依赖场景节点**，可独立跑测试。
  - 场景脚本只做「接线」：把 core 逻辑绑到节点上。
  - 数据一律 `data/` 下 JSON/Tres，不硬编码进脚本。
- 版本控制：目录 `git init` 后 `git add`，AI 每次改动可 review diff（建议后续做）。

## 九、关键风险与对策

| 风险 | 对策 |
|---|---|
| 中文字体缺失 → 方块字 | 提前打包字体 + fallback（见第二节） |
| TileMap API 变动（4.2→4.7） | 直接用 4.7 最新 API，查文档以 4.7 为准 |
| GDScript 语法不熟 | 用最简子集（类、数组、字典、for/if），AI 生成后人工过一遍 |
| 敌人 AI 太蠢/太强 | V1 脚本 AI + 数值可调；V2 换 LLM 建议 + 校验 |
| 网页导出字体/路径问题 | 导出前用 Godot 导出向导跑一遍 Web 模板，字体走 `res://` 资源 |
| 编辑器不熟拖慢节奏 | 场景文件文本化，AI 可直接生成 `.tscn`，人工只在编辑器微调 |
