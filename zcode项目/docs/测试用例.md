## 一、怎么跑测试（一条命令）

```bash
cd zcode项目
python tools/run_all_tests.py                 # 全量回归（24 个测试，约 1 分钟）
python tools/run_all_tests.py core e2e        # 只跑名字含 core / e2e 的
python tools/run_all_tests.py --list          # 看会跑哪些
```

退出码 `0` = 全过，`1` = 有失败（可直接接 CI）。

单跑某一个：

```bash
.tools/godot_extracted/Godot_v4.7.2-stable_win64_console.exe --headless --path zcode项目 \
  --script res://tests/test_core.gd
```

## 三、手工验收清单（每关必走）

> 自动化测不了"手感"和"演出"，这部分每次发版前手过一遍。

### 通用（每关都验）

- [ ] 进入关卡画面**居中铺满**（含全屏状态；此前有全屏后挤到左下角的 bug）
- [ ] 开场对白可按空格推进、可点「跳过剧情」
- [ ] 面板显示：当前阶段军令 + 预备军令 + 将缘 + 士气
- [ ] 选中单位 → 显示移动范围 → 移动 → 弹出指令气泡
- [ ] 空格按一次：若有人未行动 → **弹警告**；再按一次 → 进入敌方回合
- [ ] 全员行动完 → 弹「我方全员行动完毕」横幅（不是无声跳过）
- [ ] 敌方回合有演出节奏，能看清谁打了谁
- [ ] 胜利后：胜利对白 → 结算面板（声望/战利品/图鉴）

### 第 1 关 · 汜水关

- [ ] 阶段 1 显示「温酒斩华雄（第 1/2 阶段）」
- [ ] 刀兵要打 **3 刀**才死（不再是碰一下就死）
- [ ] 斩华雄后**不直接通关**，横幅提示阶段 2「劈关夺门」
- [ ] 关羽蓄力到 8 格时面板出现"再走 N 格"预告
- [ ] 点技能 → 点**城门格** → 蓄力不足时提示"力道不足"；满 10 格 → 城门崩塌 + 声望 +500
- [ ] 破门后才结算通关

### 第 2 关 · 虎牢关

- [ ] 阶段 1 是「坚守 3 回合」，撑到第 3 回合自动进入阶段 2
- [ ] 张飞点「咆哮」→ **直接开喊**（不需要点目标）
- [ ] 连点空格 → 字数从 6 涨到 14 → 自动释放
- [ ] 14 字怒吼震碎吕布铁皮、清空方天连击
- [ ] 关羽蓄力 10+ 时，吕布和副将改为扑向关羽（嘲讽生效）
- [ ] 骑赵云后首次受击蓄力不清零

### 第 3 关 · 谯县

- [ ] 阶段 1「乱军围将」：清光 3 个乱兵后进入阶段 2
- [ ] 许褚半血时触发裸衣（爆甲 + 吸血 + 双倍攻速）
- [ ] 阶段 2 面板提示"打到三成血以下，别下死手"
- [ ] 打到 30% 以下 → 归顺通关，**许褚不能是阵亡状态**

### 第 4 关 · 泰山郡

- [ ] 阶段 1「攻破山砦」：击破昌豨后进入阶段 2
- [ ] 臧霸站在高地格时攻防 +30%（面板/浮字有提示）
- [ ] 阶段 2「打回琅琊」：击退臧霸 → 通关

## 四、混沌测试（抓偶发 bug 的主力）

人手工点不出所有组合。`probe_chaos.gd` 随机模拟玩家操作，每步校验一组"永远该成立"的不变量：

```bash
python tools/run_all_tests.py chaos      # 只跑混沌测试（默认 60 步）
# 或指定步数 / 随机种子 / 关卡（种子固定则结果可复现）
.tools/godot_extracted/Godot_v4.7.2-stable_win64_console.exe --headless \
  --path zcode项目 --script res://tests/probe_chaos.gd -- 200 999 chapter2
```

**校验的不变量**

| 不变量 | 能抓到的 bug 类型 |
|---|---|
| 单位 id 唯一 | 重复生成/克隆单位 |
| 飞弹数据数 == 视觉节点数 | **图标残留**、隐形飞弹 |
| 已行动单位不处于可操作态（input_mode != NONE） | 放完技能还能动 |
| 点已行动单位查看后不能被移动 | "点他一下再点地面就移动" |
| 已行动单位不挂可见命令菜单 | **原地残留气泡图标** |
| 同一单位同回合不能成功移动 2 次 | **无限移动** |
| 我方单位数不凭空增加 | 刷单位 |
| 临时节点数 < 400 | **节点泄漏/卡死先兆** |
| 回合数 >= 1 | 回合状态错乱 |

> **注意判定方向**：原第 3 条曾写成 `input_mode == 0` 时报错，方向写反 → 真 bug 被漏报。
> 正确含义是"selected 指向已行动单位时，input_mode **必须**是 NONE"。

**已经靠它抓到的真 bug**：同回合重复移动（4 处）、我方全灭后回合空转 130 回合不结束（= 玩家反馈的卡住）。

> 用法建议：**每次改完战斗逻辑，跑 2-3 个种子 × 150 步**。

## 五、新需求怎么加测试

**原则：一个新机制 = 一个 `test_*.gd` 或 `probe_*.gd`，加完立刻进全量回归。**

1. **纯逻辑**（数值/条件/公式）→ 写 `test_xxx.gd`，`extends SceneTree`，用 `preload` 引被测脚本，断言失败就 `failed += 1` 并 `printerr`
2. **交互链路/场景** → 写 `probe_xxx.gd`，`change_scene_to_file("res://scenes/battle.tscn")` 后直接调内部方法（如 `_check_victory()`）
3. **⚠ 涉及输入 / 状态机的验证，必须走真实入口 `_handle_click(cell)`，不要直接调 `_do_move` / `_do_skill`**
   - 原因（2026-09-19 踩坑）：直接调内部函数会**绕过点击分派逻辑**，而 bug 恰恰藏在分派里。
     当时探针直接调 `_do_move` 去测"放完技能能否再移动"，绕过了 `_handle_click` 对已行动单位的判断，
     结论错误地写成"未复现"；改走 `_handle_click` 后立刻复现（真实 BUG：`_inspect_unit` 把状态设成了 SELECT）
   - 同类：测"空格结束回合"要走 `_input` / 对应按键处理函数，而不是直接调 `_end_player_turn()`
4. **命名要求**：以 `test_` 或 `probe_` 开头才会被 `run_all_tests.py` 自动发现；演示脚本用别的名字（已在 SKIP 名单里）
5. **失败输出规范**：用 `[FAIL] 描述` 开头，`run_all_tests.py` 靠这个正则抓失败

> 注意：**改代码前先改文档**（GDD 的期望行为），改完代码后同步更新本文件的验收项，最后跑全量回归确认。


> 注：tools/run_all_tests.py 里有 SLOW 名单，给「要完整打一遍关卡」的慢测试放宽超时（默认 90 秒）。
