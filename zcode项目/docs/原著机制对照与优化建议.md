## 二、最值得改的一项：燕人咆哮的「字数」机制

### 原著依据

- 第 1 章张飞自述：「我的绝技叫做【燕人咆哮】——**咆哮的字数越多，威力越大**。」
- 第 14 章：「张飞蓄力已久，上来就是**六字**咆哮……据说当他喊出『燕人张飞在此，谁敢与我决一死战！』**十四个字**的时候，威力甚至能把内脏震碎，根本没有人能防得住。」
- 第 14 章同段：「**群控技能，敌我不分**。附近的士兵被震得头晕目眩……**刘备提前戴好了耳塞**，症状倒是轻一些。」
- 第 14 章代价：「两次燕人咆哮消耗的能量太多了，如今连动作都没有刚才敏捷」——并非"开了就能一直放"。

### 现状问题

游戏把咆哮做成"开局即用、CD 3 回合、只打敌人、眩晕 1 回合"的固定控制技。功能上没错，但**原著里这个绝技的全部笑点和策略深度都在"字数"上**——"喊得越长越强、长到自己人也遭殃、所以刘备要提前戴耳塞"。玩家现在完全感受不到。

### 建议实现（成本约 0.5-1 人日）

| 项 | 设计 |
|---|---|
| 蓄字 | 点「咆哮」后进入蓄字状态，连点（Space/左键）累加字数，0.2s/字，最多 14 字 |
| 6 字（速控） | 眩晕 1 回合、半径 2、仅敌方 —— 即当前行为，作为"快而轻"选项 |
| 14 字（满控） | 眩晕 2 回合、半径 3、**震碎吕布铁皮 + 清空连击**、**敌我不分**（己方也晕 1 回合） |
| 耳塞道具 | 持有「耳塞」的己方单位免疫己方咆哮（原著刘备的梗）；可放进抽奖池 |
| CD | 6 字 CD 3 回合；14 字 CD 5 回合（对应原著"耗能巨大、两次就虚脱"） |

这样"张飞"从"固定套路按钮"变成"每次要权衡喊多长的赌博按钮"，同时与第二关现有教学（"用张飞怒吼震碎铁皮"）完全兼容。

## 四、背景交代：新增「序章过场」（曹操传式开场）

### 问题

原来点「进军出征」直接进战场，玩家不知道**这三人是现代穿越者**，于是所有笑点都落空：
- "华雄彻底成你们战力计量单位了"（要靠"武安国=6 倍华雄之力"的对比才成立）
- "你让子龙给我当马骑"（靠"赵云无限体力"的设定才成立）
- 关羽一开始怂、刘备不想上（靠三人是"肺雾大学生"才成立）

**这不是锦上添花，是第一关笑点的地基。**

### 已实现

新增独立过场场景 `scenes/prologue.tscn` + `scripts/prologue.gd`，数据驱动：

```
data/prologues/chapter1.json   # 18 行：穿越 / 结拜 / 霸业系统 / 三个绝技 / 华雄压境
data/prologues/chapter2.json   # 14 行：董卓抄袁家 / 吕布三击设定 / 赵云登场 / 骑着赵云去拉青龙
```

- 演出：**章节标题卡（2.4s）→ 卷轴旁白 / 人物名牌对白 / 系统面板**，逐字打字机，Space/点击推进，随时可跳过
- 流程：主菜单点章节 → 该章**首次**进入先播序章 → 进战场；看过的章节直接进关（标记存 `save["prologues_seen"]`）
- 扩展：第三/四关只需加 `data/prologues/chapter3.json` / `chapter4.json`，代码零改动

### 关于"有没有现成的轮子"

| 方案 | 说明 | 建议 |
|---|---|---|
| **自建 prologue 场景**（本次采用） | 复用项目现有 JSON 对白格式，零第三方依赖，完全贴合"墨玉金边"美术风格 | ✅ 当前规模最优 |
| Godot Dialogue Manager 插件（nathanhoad） | 现成的对话引擎：打字机、立绘、分支、条件、变量插值 | 对话量大幅上升（如做人物好感度/多结局）时再迁移更划算；迁移需改数据格式与运行时接线 |
| 现成"序章模板"素材 | 主要是 RPG Maker / Unity 资源，Godot 生态没有开箱即用的曹操传式过场 | 不推荐，改造量大于自建 |

结论：**现阶段自建是对的**；真要做"立绘 + 分支 + 好感度"，再上 Dialogue Manager。
