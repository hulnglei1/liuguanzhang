## 一、桥接（MCP-Bridge）能力补强

`zcode项目/scripts/systems/agent_bridge.gd` 新增/改进：

| 方法 | 说明 |
|---|---|
| **`get_battle_state`**（新增，只读） | 驱动"玩家操作"必需的最小状态：单位 id/阵营/格子/HP/是否已行动/是否已移动/蓄力/眩晕/是否主将/技能、当前回合、军令阶段、胜负、是否播对白、input_mode、城门格、grid_offset + tile（用于格子→像素换算） |
| `query_node_coord`（增强） | 新增可选 `class_filter` / `path_filter` |

**踩坑（很重要）**：`_query_node` 的文本匹配会命中**仪表盘上的说明文字**
（如「使用【待机】积蓄怒吼轮数」含"待机"、「✨ 专属战技机制」含"✨"），
于是 `query("待机")` 返回的是 Label 而不是按钮，点在说明文字上 → 表现为"点了没反应"。
**凡是要点按钮，必须带 `class_filter="Button"`。**

## 二、抓到一个真·游戏 bug（只有有头+真实鼠标才会复现）

`battle.gd` 命令菜单的点击放行判断写着：

```gdscript
if m_rect.has_point(event.position) or m_rect.has_point(get_global_mouse_position()):
    return
```

后半个条件是**鼠标物理位置**。只要玩家的鼠标恰好停在菜单那片矩形内，
**哪怕点的是棋盘另一头，整个点击事件也会被吞掉** —— 典型症状"点哪儿都没反应"。

- 已改为**只看 `event.position`**。
- headless 之所以一直没暴露：窗口只有 64×64，菜单矩形与实际点击坐标对不上。

## 三、有头 MCP 驱动脚本：`.tools/tmp/mcp_play_styles.py`

- 真实窗口启动游戏 → 连 `127.0.0.1:9099` → 发**真实输入事件**（`Input.parse_input_event`）
- 严格照玩家的操作顺序：**点我方单位选中 → 点绿格移动 → 再点自己弹菜单 → 点「⚔️ 普通攻击」/「✨ 绝技」 → 点目标**
- 多种"玩家性格"各打一遍第一关，抓关键截图到 `.tools/tmp/mcp_shots/`
- 内置防卡死：某单位连续 3 次动作未生效 → 强制待机；连待机都点不动 → 本回合放弃
- 用法：`python .tools/tmp/mcp_play_styles.py 莽夫型 技能流 ...`（不带参数=4 种常规风格）

**结果**：莽夫型 **16 回合通关 ✅**（真实点击链路全通：选中/移动/弹菜单/菜单攻击/关羽蓄力 13 次后劈城门）。

**踩坑**：
1. 胜利后**必须先按空格把胜利对白推完**，结算面板才会出现「返回主城 🏰」；
   否则脚本卡在战斗场景，后续风格全部"无法回到主菜单"（第一版就栽在这）。
2. Godot 的 `--script` 模式下主场景不会自动加载；但 MCP 驱动是正常启动游戏，没这个问题。

## 五、有头 MCP 测试终局结果（4 种常规风格，全部通关）

| 风格 | 打法 | 回合 | 结果 |
|---|---|---|---|
| 莽夫型 | 全员冲最近敌人，只普攻 | 13 | 通关 ✅ |
| 技能流 | 有技能就放 | 12 | 通关 ✅ |
| 龟缩型 | 不主动移动，原地反击 | 12 | 通关 ✅ |
| 精准型 | 集火血最少 | 9 | 通关 ✅ |

无一条"动作未生效"警告，无卡死。截图在 `.tools/tmp/mcp_shots/`。

**关键保真修正（第一版误判）**：驱动一开始用"曼哈顿距离==1"当攻击范围，
**漏掉远程单位** —— 龟缩型的公孙瓒（rng≥2）从头到尾一箭没放，被误判成"20 回合打不过"。
改成**让游戏自己判定**：菜单里「⚔️ 普通攻击」按钮的 disabled 状态 = 当前射程内有没有目标；
再挨个点候选目标，点到 `acted=true` 为止。改完龟缩型 12 回合通关。
> 教训：**自动化里不要替游戏猜规则**，能问游戏就问游戏。用户那句"模拟真实玩家的操作方法"
> 其实就是在说这件事——玩家的每一次操作都会得到游戏的即时反馈，脚本也该照这个来。
