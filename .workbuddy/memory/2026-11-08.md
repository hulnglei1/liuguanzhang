## 追加：动画节奏（用户澄清"慢"指动画本身，不是停顿）

三个真问题（都不是我最初以为的"敌方回合停顿"）：
1. `_animate_move` 每格 `tween_interval(0.06) + tween_property(0.06)` = **0.12 秒/格**，而且**先等再动**，起步就迟钝
2. `_do_move` 只 `await moved_cells * 0.06`，**只有动画时长的一半** → 单位还没走到位，命令菜单就弹出来了
3. 攻击帧 6fps × 4 帧 = **0.67 秒**，比冲刺位移（0.45s）还长，动作被帧动画拖住

改：
- 走格 0.045 秒/格（去掉前置 interval），等待时长与动画对齐（新增 `MOVE_SEG_TIME` 常量）
- 攻击位移 0.16/0.07/0.22 → 0.11/0.04/0.14（0.45 → 0.29 秒）
- 攻击帧 6fps → 10fps（0.67 → 0.4 秒）

> 教训：**"动画慢"要拆成"位移时长 / 帧速 / 等待时长"三件事分别量**，
> 只调其中一项没用——这次是三者叠加才显得拖沓，且等待与动画还不一致。

## ⚠️ 重要操作教训：taskkill 在 Git Bash 里没生效，导致测了旧代码

因为杀进程失败，**堆积了 5 个 Godot 实例**，全都抢 127.0.0.1:9099；
RPC 一直连到**最老的那个旧实例**上——后面几轮"验证"全在测旧代码。

症状与误判：
- 序章"一次空格跳两行""进入就 9/19" → 其实是旧实例行为
- 我据此加了"输入冷静期"（改动本身无害，但**不是**真因）
- 用户看到的"程序总是不关"也是同一个根因

**唯一可靠做法**：用 PowerShell 工具执行
`Get-Process | Where-Object { $_.ProcessName -like "*Godot*" } | Stop-Process -Force`
Git Bash 下 `taskkill //F //IM xx.exe` 的开关会被路径转换吃掉，**静默失败**。

**纪律**：每次截完图/测完游戏，立刻清进程再进下一步；开新实例前先确认 `tasklist | grep -ci godot` == 0。

### 虎牢狂力：原来错得离谱
玩家问"华雄的压迫感不应该一开始就狂力叠层很高吗？狂力叠层和原著差别太大"。

**我们原来的三个错**：
1. 每回合自动叠层（原著是**斩杀敌将**才叠）
2. **叠层有两处同时在加**（`unit.end_turn` +1、`battle` 击杀 +1）→ 双重叠加

## ⚠️ 关键环境坑：git push 走主站不通，但 GitHub API 通（2026-11-09）

**现象**：`git push` 报 `schannel: failed to receive handshake`，但 `curl` 调 `api.github.com` 正常。

**根因**：
- 环境变量代理 `HTTPS_PROXY=http://127.0.0.1:1818` —— **只放行 api.github.com，不放行 github.com 主站**
- git 自己配的 `http.proxy=http://127.0.0.1:7897` —— 这个端口已失效

**解法**：写了 `.tools/push_via_api.py`，用 API 完成
`建 blob → 建 tree → 建 commit → PATCH refs/heads/main`，完全绕开主站。
- 取 token：`git credential fill`（wincred 里存着 PAT）
- 中文路径要用 `git diff --name-only -z` 拿原始路径，否则被转义成 `\351\241...`
- **副作用**：API 生成的 commit SHA 与本地不同 → 本地与远端短暂分叉，`git fetch` 也走不通。
  网络恢复后执行 `git fetch origin && git reset --hard origin/main` 对齐（文件内容一致，不丢改动）。
  **在网络恢复前不要用 `git push`**（会报 non-fast-forward），一律走 API 工具。

**顺带**：改仓库可见性也走 API：`PATCH /repos/{o}/{r}` with `{"visibility":"public"}`，
设置标签用 `PUT /repos/{o}/{r}/topics`（PATCH 里的 topics 字段不生效）。

## 浏览器自动化的教训（agent-browser）

`agent-browser open <url>` 在这台机器上**第一次跑挂死了**，留下一个关不掉的空白窗口。
原因大概率是 Chromium 未安装完成，`open` 时在后台下载/启动而没有超时保护。
- **规矩**：`agent-browser install` 先单独跑（带超时）→ 再 `open`，每步都加超时
- 不要再让 `open` 裸跑在前台
- 出问题用 PowerShell 强杀：`Get-Process chrome,chromium,agent-browser | Stop-Process -Force`
