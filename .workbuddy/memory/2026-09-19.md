## 二、真 BUG 复现：「放完技能还能移动」
**上一轮我判断"未复现"是错的** —— 当时探针直接调 `_do_move` 绕过点击入口，结论不可信。

### 根因（`battle.gd: _inspect_unit`）
```gdscript
func _inspect_unit(id):
    selected_id = id
    input_mode = InputMode.SELECT   # ← 致命：只是"查看信息"却进入可操作态
```
玩家路径：公孙瓒放完技能（acted=true）→ 玩家点他"查看" → `_inspect_unit` 把状态设为 SELECT
→ 玩家再点地面 → `InputMode.SELECT` 分支的 `_is_in_reachable` → `_do_move` 成功 → **又能移动**

### 修复（三条防线）
1. `_handle_click` **统一前置**：点到"已行动完毕的我方单位"一律走 `_inspect_unit`，不进状态机
2. `_select_unit` 加纵深防御：命中已行动单位 → 清 selected_id / input_mode，直接返回
3. `_do_move` 加 `u.acted` 兜底；`_show_command_menu` 对 acted 单位顺手清 `input_mode`（原来只隐藏菜单，残留 POST_MOVE）
4. `_inspect_unit` 的 input_mode 改为 `NONE`（不再是 SELECT）

## 三、混沌测试的两处缺陷（比 bug 本身更重要）
1. **不变量 3 判定方向写反**：写成 `sel.acted and input_mode == 0` 才报错 →
   真正危险的 `input_mode != NONE` 反而漏报。已改为 `!= 0`
2. **随机操作从不点已行动单位** → 该路径零覆盖。已新增 `_inspect_acted_check()`：
   每 5 步模拟"点已行动单位查看 → 再点旁边地面"，校验不移动、不进入可操作态
3. 新增不变量 7：已行动单位不应还挂着可见命令菜单（对应"原地残留 2 个小图标"）

复现证据（修复前）：`gongsunzan input_mode=5(POST_MOVE)`、`位置 (2,3) → (2,4) 移动成功`
修复后：3 组混沌 115/172/41 步全过

## 七、机制侧第一个修复：武安国剧情一致性（已完成）

**问题**：第 2 关第 3 回合剧情写"武安国连人带锤倒飞、当场吐血脱力"，
但游戏里他仍是满血 160、DEF 不变、照样行动 —— 剧情与状态完全脱节。

**根因（两层）**：
1. 剧情事件只播对白，**不改变任何状态**
2. 已有的 `exhausted` 是另一套逻辑：武安国**自己挥锤后** DEF-30%、**次回合就恢复**

**修复**：
- `unit.gd`：新增 `exhausted_turns: int` + `set_exhausted(turns)`（取较长者，不叠加）；
  `end_turn()` 改为递减；`to_dict()` 补字段
- `skills.gd`：挥锤 `caster.exhausted = true` → `caster.set_exhausted(1)`（**行为不变**）
- `battle.gd`：`_check_turn_events()` 支持 `events[].effect`；新增 `_apply_event_effect()`
  实现 `smash_unit`（按 攻击×倍率 扣血，**保底 hp_floor_ratio 不致死**，再施加长期脱力）
- `chapter2.json`：`chapter2_wuanguo_fall` 挂 `effect`（mult 3.0 / floor 0.3 / 脱力 3 回合）

**实测**：HP 160 → 66、DEF 12 → 8（-30%）、脱力 3 回合、残血(5)时只脱力不扣死。
原著依据：武安国是被打飞**抬下去**，不是战死 —— 所以保底不死是刻意的。

**设计原则（写进 GDD §4.5）**：**剧情描写必须与单位状态一致。剧情说某人被打了，血条就得真的掉。**
`events[].effect` 是数据驱动的通用钩子，后续关卡可直接复用。

新增 `tests/probe_wuanguo.gd`；全量回归 **29 通过 / 0 失败**。

## 十、附带修复：跑全量测试会清空玩家存档

**问题**：`tests/` 下的探针结尾都会执行 `SaveCore.save_state(SaveCore.new_state())`
（为了让测试可复现，从干净存档开始）。跑一次全量回归，玩家辛苦打的
章节进度 / 声望 / 背包 / 序章标记 **全被清掉**。用户存档里 5555 声望 + 通关记录就这样没的。

**修**：`tools/run_all_tests.py` 的 `__main__` 外面包一层保护——
1. 跑测试前把 `%APPDATA%/Godot/app_userdata/魂穿刘关张 · 战棋/save.json` 备份为 `save.json.userbak`
2. `try/finally` 保证无论成败都还原
3. 还原时打印 `[已还原玩家存档]`，让人看得见

**已验证**：跑测试前后存档内容逐字节一致。

> 教训：**动用户数据的自动化必须有备份/还原**。测试"重置存档"是合理设计，

### 测试基础设施的两个坑（以后写玩家视角测试必看）
1. **headless 下窗口只有 64×64**（`root.size` 设不动，实测 `(64,64)`），

2. UI 按钮（主菜单「进军出征」、技能按钮）在 headless 下**坐标点击无效**
