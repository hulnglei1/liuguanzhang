## 二、真 BUG 复现：「放完技能还能移动」
**上一轮我判断"未复现"是错的** —— 当时探针直接调 `_do_move` 绕过点击入口，结论不可信。

### 根因（`battle.gd: _inspect_unit`）
```gdscript
func _inspect_unit(id):
    selected_id = id
    input_mode = InputMode.SELECT   # ← 致命：只是"查看信息"却进入可操作态
```
玩家路径：公孙瓒放完技能（acted=true）→ 玩家点他"查看" → `_inspect_unit` 把状态设为 SELECT
→ 玩家再点地面 → `InputMode.SELECT` 分支的 `_is_in_reachable` → `_do_move` 成功 → **又能移动**

### 修复（三条防线）
1. `_handle_click` **统一前置**：点到"已行动完毕的我方单位"一律走 `_inspect_unit`，不进状态机
2. `_select_unit` 加纵深防御：命中已行动单位 → 清 selected_id / input_mode，直接返回
3. `_do_move` 加 `u.acted` 兜底；`_show_command_menu` 对 acted 单位顺手清 `input_mode`（原来只隐藏菜单，残留 POST_MOVE）
4. `_inspect_unit` 的 input_mode 改为 `NONE`（不再是 SELECT）

## 三、混沌测试的两处缺陷（比 bug 本身更重要）
1. **不变量 3 判定方向写反**：写成 `sel.acted and input_mode == 0` 才报错 →
   真正危险的 `input_mode != NONE` 反而漏报。已改为 `!= 0`
2. **随机操作从不点已行动单位** → 该路径零覆盖。已新增 `_inspect_acted_check()`：
   每 5 步模拟"点已行动单位查看 → 再点旁边地面"，校验不移动、不进入可操作态
3. 新增不变量 7：已行动单位不应还挂着可见命令菜单（对应"原地残留 2 个小图标"）

复现证据（修复前）：`gongsunzan input_mode=5(POST_MOVE)`、`位置 (2,3) → (2,4) 移动成功`
修复后：3 组混沌 115/172/41 步全过

## 五、方法论教训（已写进《测试用例.md》第五节）
**验证输入/状态机类 bug，必须走真实入口 `_handle_click`，不能直接调 `_do_move`/`_do_skill`。**
bug 常常藏在"点击分派"这一层，直接调内部函数会绕过它 —— 上一轮就是这样漏判的。
